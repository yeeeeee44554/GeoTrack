# GeoTrack 需求规约（SDD Requirements v2）

**状态**：Accepted  
**版本**：0.2  
**适用范围**：GeoLife Trajectories 1.3 的 GPS 轨迹清洗、出行模式挖掘、热点区域分析和 Web 演示  
**规格索引**：[`docs/specs/README.md`](specs/README.md)

本文件采用“需求编号 + 优先级 + 验收证据”的结构。原始 `docs/requirements.md` 保留为早期草案；本文件与阶段 Spec 一起作为当前实现的结构化需求基线。

## 1. 背景与问题

GeoLife 轨迹以用户目录和 PLT 文件保存，数据量大、采样间隔不一致、部分点存在异常。课程项目需要展示大数据处理链路，同时让答辩者可以快速观察北京高密度区域的轨迹、停留点、热点和时间模式。因此系统采用“全量批处理证明规模 + 演示子集保证交互”的口径。

## 2. 用户与场景

| 角色 | 目标 | 关键场景 |
| --- | --- | --- |
| 分析者 | 理解轨迹和城市热点 | 查看总览、筛选用户/时间/空间、点击热点 |
| 演示者 | 在限定时间内展示系统价值 | 依次演示总览、轨迹、热点、模式、任务 |
| 批处理管理员 | 运行和追踪数据处理 | 提交 ingest/mine、轮询 job_id、查看质量 |
| 教师/评审 | 判断课程合规和实际贡献 | 检查四层架构、Git、Spec、Prompt、测试和报告 |

## 4. 业务规则

### BR-001 数据口径

官方规模固定记录为 182 个用户、18,670 条轨迹、约 24,876,978 个轨迹点。当前演示结果必须单独显示实际处理的用户、轨迹和点数，不得混淆两种口径。

### BR-002 时间与空间

时间按 GMT 解析并以 UTC ISO-8601 输出；GeoJSON 坐标顺序为 `[longitude, latitude]`；Leaflet 内部显示转换为 `[latitude, longitude]`；距离统一为米。

### BR-003 参数

停留半径 200m、最短停留 20 分钟、断点 30 分钟；热点 `eps=500m`、`minPts=3`；模式 `k=3`、`seed=42`。覆盖默认值的任务必须把实际参数写入结果或任务日志。

### BR-004 解释

聚类必须保留原始 cluster id、中心特征和样本数量。中文标签只描述可观测的峰值小时、距离、时长和工作日比例，不表示人工标注真值。

## 5. 非功能需求

| ID | 需求 | 可测量目标 |
| --- | --- | --- |
| NFR-001 | 数据合规 | 原始 GeoLife、课程 PDF、密钥不进入 Git |
| NFR-002 | 查询性能 | 演示子集关键 API 目标响应不超过 3 秒 |
| NFR-003 | 可重复性 | 相同输入和参数生成相同业务字段，批次有 run_id/时间 |
| NFR-004 | 可用性 | API 失败时页面可用 demo seed，异常有可读提示 |
| NFR-005 | 可扩展性 | 全量计算走 Spark/HDFS，页面通过预计算结果查询 |
| NFR-006 | 可维护性 | 每个阶段拥有 Spec、Prompt、测试或人工验收记录 |
| NFR-007 | 可审计性 | 需求条款可追踪到代码、测试、报告章节和提交号 |

## 6. 验收矩阵

| 层次 | 验收项目 | 通过条件 |
| --- | --- | --- |
| 数据 | 解析与质量 | 头部、GMT、非法坐标、`-777`、重复点、断点有测试 |
| 算法 | 距离、停留、DBSCAN、KMeans | 已知样例通过，输出字段完整，参数有记录 |
| 大数据 | HDFS/Spark | raw/curated 路径、Parquet、质量摘要可说明并可运行 |
| 数据库 | PostGIS/MobilityDB | Schema、索引、upsert、dry-run 通过 |
| API | 查询和任务 | JSON 契约、错误码、job_id、分页和筛选通过 |
| 前端 | 交互和状态 | 五个视图、地图联动、图表、窄屏和回退可演示 |
| 课程 | 交付物 | Spec、Prompt、报告、贡献表、PPT、MP4 和 Git 历史齐全 |

## 7. 需求追踪和变更

所有实现需求使用 `FR-*`、`NFR-*`、`BR-*` 编号。阶段变更通过新增或修订 Spec 记录，保留原文件和 Git 提交，不删除已经验收的历史。最终报告必须列出未完成条款、原因、替代方案和实际贡献。

## 8. 限制和假设

- Spark/HDFS/MobilityDB 镜像受本机资源和网络影响，未在目标机器验证的内容必须明确标记。
- 标签只覆盖部分用户，交通方式识别延期到后续 Spec。
